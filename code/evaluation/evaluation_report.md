## How we evaluate

| Layer | What is measured | Where |
|---|---|---|
| Case level | `deletion_status` accuracy + 3×3 confusion matrix on the 32 labelled samples | `score()` |
| Step level | precision / recall / F1 over `(phase, system_id, resource_id, operation, state)` tuples | `score()` |
| Field level | per-field accuracy on index-aligned steps; `evidence_id` accuracy on matched steps | `score()` |
| Sequence | exact ordered match of step tuples + mean normalized Levenshtein similarity | `score()` |
| Contract invariants | header, 518 rows, natural case order, valid JSON, consecutive `step_no`, legal op/phase/state, canonical order, empty evidence on future steps, COMPLETE steps evidenced, no evidence captured after `audit_at` | `invariants()` on every run |
| Custom cases | 8 hand-specified fault injections on copies of the dataset | `custom_cases.py` |
| Ablations | each component switched off in turn; sample metrics, custom cases, rows changed on the 518 test requests | `run_ablations()` |
| Determinism | two consecutive runs must produce byte-identical `output.csv` | checked with `cmp` (system.md) |

## Additional evaluation cases created by the team

hand-derived expected answer:

| ID | Scenario | Expected behaviour |
|---|---|---|
| C1 | Request uses the subject's **old email** (changed in `user_audit_log` before the request) | Same answer as the original case — identity resolved through history |
| C2 | A **sync re-creates** the profile after a SUCCESS delete; a later readback finds it | `INCOMPLETE`: REPORT_REMAINING_RECORD citing the readback → DELETE → VERIFY_ABSENT |
| C3 | An **account tombstone still exposes an identifier** | `INCOMPLETE`: REPORT_EXPOSED_PII → REDACT_RECORD → VERIFY_RECORD_REDACTED; other verifications unchanged |

## Known limitations (data-level ceilings)

- **Unobservable gold resources**: `account_004`, `audit_record_6645`, `audit_record_5569` appear in no participant
  evidence (text or screenshots); no solver can derive them.
- **Identical `reported_at`**: requests reported at the same instant (e.g. samples 24–26, 27–29, 31–32) whose deleted
  accounts carry no identifiers are separated only by workflow timing; activity order, `requested_at` and timing gaps
  were checked and carry no further signal, so some account assignments are swapped. This is the main source of the
  remaining step errors on the samples.
- Screenshot facts depend on the vision model; every extraction was validated against resource-id patterns and the
  11 images were spot-checked by hand.
